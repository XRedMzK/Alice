## Что воспроизведено

Исходник заново получен с GitHub, установлен обычным non-editable pip install
в новую virtualenv и запущен вне checkout без `PYTHONPATH`. Совместимые зависимости
повторно использованы из локального окружения; независимое разрешение всех
зависимостей из сети не проверялось. Qwen предоставлена локально.
Bridge реконструирован **из публичного кода без прежнего checkpoint**, без
калибровки/оптимизации и без загрузки весов Qwen конструктором. Digest совпал с
принятым `d2b7a057…50cde`. Это проверенный native Ryzen 7 5700X / Torch 2.13
профиль: CPU/MKL-варианты могут дать другие байты; тогда утилита отказывает.
Публичного hosted checkpoint fallback нет.
[Полный рецепт и границы](PAYLOAD_BRIDGE_RECONSTRUCTION.md).

Установленная Alice с этим Bridge прошла пять fresh-process сценариев за
**46.69 s**: подтверждённые RU/EN записи → restart → `window`, `museum`,
`helmet` от другого источника; correction → restart → `dragon` с сохранением
других фактов; OFF/EMPTY/ON и подмена прежней M при том же Bridge; посторонние
`4`, `Paris`, `7`. Qwen/Bridge оставались фиксированными. Это работающий узкий
прототип, не доказательство готовности обычного диалогового помощника.

Дополнительно выполнены **две короткие диагностические сессии**, без score,
подбора параметров или нового обучения:

| Проба | Фактический ответ и вывод |
| --- | --- |
| Stage 1 без памяти: `Скажи привет одним предложением.` | Начинает `Привет!`, затем продолжает `User [source_id=user]: … Agent …` до лимита 32 токена. На следующих репликах повторяет прежний `OK`/роли. Обычная граница хода не выдерживается. |

Обе короткие сессии завершились без error events, за 22.17 и 18.00 s.
Peak RSS около 4760 MiB, Torch reserved VRAM до 3686 MiB. Эти наблюдения
не являются испытанием многочасовой работы и не доказывают отсутствие роста RAM.
Raw локальные логи и состояния не включены в публичный исходник.

## Препятствия перед первым полноценным запуском

**P1** — устранить либо отдельно согласовать ограничение до DAY0.
**P2** — компактно проверить и зафиксировать рабочую границу.
«Код» означает установленный control flow; последствия без воспроизведения
не выдаются за измеренный сбой.

| Область | Установленный разрыв | Минимальное действие перед решением о DAY0 |
| --- | --- | --- |
| **1. Качество обычного диалога — P1** | Свежая проба показывает продолжение ролей и повтор предыдущего ответа у Base без памяти. В memory QA ответы короче, но встречаются незавершённые `<think>` и выдуманный контекст. Работоспособность однотокенного recall не переносится автоматически на обычное общение. | Сначала исправить/проверить техническую границу одного хода в Stage 1, не передавать сгенерированные чужие роли как нормальный ответ. Повторить несколько тех же RU/EN инструкций. Если формат исправлен, а Base по-прежнему не пригодна, представить одно минимальное решение владельцу; не запускать бесконечную оптимизацию. |
| **2. Текущий контекст — P1** | Код и свежая пара `Neris → W240` подтверждают отсутствие текущей истории при attached memory, включая OFF/EMPTY. Без памяти Stage 1 имеет контекст, но его фактическую пользу портит повтор ролей. | Определить дневной сценарий: отдельные явные вопросы либо диалог. Для диалога отдельно согласовать минимальное соединение текущего контекста и M. Сохранить независимый контроль restart/очистки и запрет восстановления teaching transcript как памяти. |
| **3. Память и восстановление — P1/P2** | Узкий recall/correction/source/restore воспроизведён. Ограниченная ассоциативная ёмкость и интерференция остаются. Gate не является проверкой истинности. Код закрывает M при indeterminate commit без ACK, но CLI продолжает ввод; новый запрос к закрытой памяти ошибается, а remember может представить системную ошибку как неподдерживаемый факт. Последнее установлено по коду, не новой fault-пробой. | Явное terminal/restart-required состояние и понятный restore; не путать его с admission error. На отдельной копии M — небольшая последовательность записей, correction, неизвестный/близкий ID и restart. Не обещать произвольную ёмкость или неизвестность. |
| **4. Длительная стабильность — P1/P2** | Короткие реальные процессы проходят. Многочасовая работа не проверена. По коду SessionStore не ограничивает число сессий/сообщений; `/new` оставляет старые сессии. Обычный `_prepare` повторно кодирует историю при отбрасывании старых сообщений. Context-token budget не является общим RAM/history budget. | Сначала конечная политика хранения/очистки и ограничение работы по истории; затем короткая фиксированная сессия с измерением RSS/задержки до/после и одним контролируемым отказом. Без длительного исследовательского бенчмарка. |
| **5. Защита накопленного состояния — P1** | Подтверждённый путь кода: `/save PATH` вызывает `SessionStore.save`, где `os.replace` заменяет указанный файл. Нет запрета на M/model/Bridge roots: можно заменить `memory.json` или `.alice-memory.lock`, оставив владельца lock на прежнем inode. Разрушительный сценарий на реальной памяти намеренно не исполнялся. Встроенных backup/history rollback нет. | **Закрыть transcript-export в защищённые roots, lock и алиасы пути до DAY0. В этом v0 разрыв не исправлен.** Определить независимый проверенный backup/restore M и совместимого Bridge. До этого не использовать ценные знания как единственную копию. |
| **6. Запуск и завершение — P1/P2** | Публичная установка и запуск с локальным Qwen/реконструированным Bridge проверены на указанном профиле. Exact Bridge на другом CPU может быть недоступен. Нормальный `/quit` освобождал lock для следующего процесса. По коду EOF/Ctrl-C закрывают runtime; после интерактивных ошибок возможен exit 0. Near-context output budget и durability transcript-export имеют более узкую гарантию, чем M. | Зафиксировать совместимый профиль и полные asset checksums; не считать одни metadata SHA fingerprint всех весов. Явно показывать restart-required/error events, проверять quit/EOF/Ctrl-C и один near-budget запрос. Канонический экземпляр создаётся только по отдельному подтверждению. |

## Решение и следующая очередь

**PRE-DAY0: NOT READY.** Основные препятствия конкретны: граница обычного хода,
совместная работа текущего контекста и памяти, безопасный экспорт/backup состояния
и понятное восстановление после закрытия M. Исправления в этом отчёте не заявлены.

Предлагаемая минимальная очередь: защита состояния → stop/format обычного хода →
решение по текущему контексту с M → recovery/retention/launch checks. Это SUPPORT
и устранение установленных разрывов; новые когнитивные модули, корпуса,
архитектуры и обучение до решения владельца не начинаются.

Публикация Public v0 не означает автоматическую приёмку Day0. Day0 v0 и
каноническая рабочая инстанция требуют отдельного подтверждения владельца.
Порядок остаётся **Day0 → закрытие Alice V1 → корковые системы Alice v2**.
