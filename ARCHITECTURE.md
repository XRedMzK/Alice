# Alice Public v0 architecture

Candidate branch scope: inference-only response boundaries, safe support-state
export, terminal recovery state, paired M/Bridge backup/restore, and bounded
history retention. Published M/Bridge schemas and neural architecture are
unchanged. An opt-in active-context prefix around the existing neural QA layout
failed real semantic integration; it is not accepted architecture or a new
cognitive module. See [PRE-DAY0 candidate](docs/PRE_DAY0_CANDIDATE.md).
The baseline description below records public `faa03d3`; its unsafe `/save PATH`
API is deliberately closed on this branch in favor of explicit create-only export.

Public v0 combines the frozen-Qwen Stage 1 runtime, independently persisted
Neural Memory and bounded confirmed RU/EN acquisition. Publication is authorized
by the owner on 26 October 2026; it is not Day0 acceptance. See [STATUS](STATUS.md)
and the [PRE-DAY0 gap report](docs/PRE_DAY0_V0_GAP_REPORT_RU.md).

## Implemented path and ownership

- **Qwen3.5-2B-Base:** local-only text loading and generation, frozen parameters,
  explicit participants, sessions and an optional typed embedding port. No model
  weights are distributed and no Qwen update occurs during acquisition.
- **Neural Memory:** independent FP32 parameters
  `[sources,17,128,128]`, own manifest/payload and fixed source registry. A
  confirmed one-token value changes only M. Correction, restart, OFF/EMPTY/ON
  and same-Bridge state substitution work in the bounded demonstrated profile.
- **Embedding Memory Bridge:** a separately saved full-rank payload codec and
  fixed Fourier query keys. Neural values continuously influence input embeddings;
  acquired values are not decoded into a text prompt or retrieved from a fact
  dictionary. The accepted Bridge stays frozen during acquisition. Its recorded
  state can be [reconstructed on a compatible CPU profile](docs/PAYLOAD_BRIDGE_RECONSTRUCTION.md)
  without fitting; exact identity across all CPU/MKL backends is not promised.
- **Dialogue support:** a deterministic explicit RU/EN object-label grammar,
  literal object IDs, one transient session/source/content-bound proposal and an
  opaque confirmation ID. Control replies are templates. Recalled answers are
  generated by Qwen. This does not implement free natural-language extraction.

The same Qwen instance supplies query/value features and generation. In memory
mode the model sees the current question only, including OFF/EMPTY. The ordinary
Stage 1 history/context profile exists without attached memory. Combining useful
current dialogue context and acquired memory remains a PRE-DAY0 gap.

M belongs to Alice independently of a session or UI. Bridge/model/state paths
must be separate and compatible; replacement never authorizes resetting M.
The current latent basis and codec are donor/Bridge-bound. Arbitrary replacement
of a donor or Bridge needs its own verified compatibility/migration. Independent
lifecycle does not establish universal tensor or behavioral interchangeability.

## Persistence and known protection boundary

A successful acquisition acknowledgement follows synced immutable parameter
publication and an atomic manifest switch. Precommit errors preserve the prior
state. Indeterminate publication sends no Saved acknowledgement, closes memory
and requires restore; missing ACK does not prove that nothing committed.
Integrity, locking, owned-staging recovery, I/O/fsync and process-kill paths have
asset-free tests. Physical power-loss durability on every filesystem is not
claimed. This release targets Linux local filesystems with rename/fsync/flock.

The interface assumes a trusted local operator. Transcript `/save PATH` currently
can replace active memory/Bridge/model files, including the lock pathname.
That omission is recorded, not fixed here, and must be resolved before Day0.
There is no built-in backup history. Source IDs are attribution, not multi-user
authentication. See the gap report before using valuable acquired state.

## Foundation compatibility boundary

The existing frozen [MODULE_CONTRACT.md](MODULE_CONTRACT.md), machine-readable schemas,
manifests, fixed synthetic graphs, source, thresholds and original tests are copied
without semantic changes. Structural modularity alone is not functional
specialization. An interface match alone does not establish behavioral compatibility.
The orchestration layer remains semantics-blind; cognitive state belongs to its
module, not the scheduler.

Foundation's current neural API uses contiguous float32 sequence tensors
`[batch, time, feature]` and owned `[batch, feature]` private state. This is not
proof of arbitrary Qwen/Bridge compatibility. Start with existing interfaces;
introduce an adapter or versioned successor only for a demonstrated need. Do not
redesign Foundation in anticipation of an unselected memory algorithm.

The [original architecture baseline](docs/FOUNDATION_ARCHITECTURE_V0.md), historical
ADRs and acceptance reports retain their dates and scope. Their references to old
work-package authority, not-yet-run operations or future models describe the
historical package. They are not orders to resume M1 or implement a new mechanism.
Any future contract change needs explicit versioning and affected evidence.

## Next boundary: Day0 before further cognition

Keep Collab: reuse a needed function rather than adopt an entire model or add a
network for an old M-number. Engineering First requires useful behavior and
necessary regression controls, not M1-style scientific qualification. No
mandatory M0–M13 module sequence is introduced.

The next work is analysis and minimal handling of the concrete PRE-DAY0 gaps:
ordinary dialogue, current context, safe memory recovery, finite session
retention, state protection and launch/quit usability. No new cognitive module,
architecture or training is started by publication. Day0 and a canonical working
instance require a separate owner decision. Close Alice V1 before moving to
cortical Alice v2 systems. The [roadmap](ROADMAP.md) records this order.
